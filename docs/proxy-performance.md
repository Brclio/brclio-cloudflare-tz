# v1.0.5 代理连接与测速改进

基于 `cmliu/edgetunnel` 的 `448a83ced00a43c1d892d5ecbed86a26ea9eeaff`，在保留转发队列、合包、回退策略和代理握手实现的基础上，修复额外等待与请求串扰。

## 连接路径

| 模式 | v1.0.4 的白名单读取 | v1.0.5 的白名单读取 |
| --- | --- | --- |
| 无链式代理，直连 / ProxyIP 回退 | 每个隧道读取一次 KV | 0 次 |
| 全局 SOCKS5 / HTTP / HTTPS / TURN / SSTP | 每个隧道读取一次 KV | 0 次 |
| 按白名单选择的非全局链式代理 | 每个隧道读取一次 KV | 保留一次，以取得该请求的路由快照 |

判断依据是已解析的节点路径与查询参数，包含代理别名和编码链式路径。跳过读取不会改变出口选择。需要白名单时仍读取已保存的配置，没有额外引入长期应用缓存；已建立的连接保留自己的快照。

面板保存 ProxyIP、链式代理账号、全局模式或传输协议后，需要在 Clash Verge **更新订阅**。这些设置通过节点路径传递给隧道；白名单才是运行时读取 KV 的例外。Cloudflare KV 仍遵循自身的最终一致性与缓存规则。

## 请求隔离与内存工作

- 默认直连并发保留为 2，中国移动网络为 1；ProxyIP 候选并发保留为 1，DoH 预加载竞速默认关闭。
- 拨号参数现在是每个请求独立的不可变快照。移动网络请求不会再让后续其他运营商的默认并发一直停留在 1；后来的请求也不会改写已打开隧道的参数。
- `TCP_CONCURRENT_DIAL` / `PROXY_CONCURRENT_DIAL` 取正有限数并向下取整，限制为 1–6；无效值回退到该请求的默认值。Cloudflare 对同一调用的待建立出站连接设有 [6 个并发限制](https://developers.cloudflare.com/workers/platform/limits/#simultaneous-open-connections)，提高数值不等于提高带宽。
- 保留原版 1000 ms TCP 建连超时，成功、失败、超时后都清理对应定时器。
- gRPC 先完整验证 protobuf，只有一个数据字段时返回原缓冲视图，省去一次载荷分配与复制。MultiHunk 仍正确合并多个字段，非法尾部仍报错。

## 测速必须经过真实出口

原版及 v1.0.4 对 `speed.cloudflare.com`、`cp.cloudflare.com` 及其子域有特殊处理：无链式代理时在 Worker 本地返回 HTTP 204，不访问目标。这会让部分 HTTP 延迟结果只反映入口，且可能干扰访问这些域名的 TLS 数据或实际下载。

v1.0.5 删除这项特殊处理。VLESS / Trojan 的 WS、gRPC、XHTTP 以及 Shadowsocks 的 WS 都按普通目标转发，测速网站的 HTTP 请求与 TLS 数据也经过实际 socket / 回退出口。

升级后，这些地址的延迟数字可能上升，原先被短路的出口问题也可能表现为测试失败。应结合真实页面与下载判断，不能用旧版的本地响应和新版的完整链路耗时直接比较。

## 在 Clash Verge 验收

1. 用构建后的完整 `dist/_worker.js` 或 `dist/brclio-edge-pages.zip` 更新部署；不要只复制 `src/worker.js`。核对后台版本为 `1.0.5`，然后更新客户端订阅。
2. 对照原版 / 旧版时固定入口 IP、端口、协议、节点路径中的 ProxyIP 或链式出口；保持 Clash Verge 的测试 URL、统一延迟开关、DNS 和网络环境一致。
3. 选固定节点交替测几轮，分开记录首次和后续请求、失败次数、延迟中位数；避免同时测试大量节点把本地网络占满。
4. 另选固定目标文件，在同一出口下有限次下载，记录耗时和实际收到的字节。延迟的 ms 与吞吐量的 Mbps / MB/s 是不同指标。
5. 若仍使用随机生成的 16 个入口，先在自己的网络筛选后保存到地址列表，并关闭随机地址模式、更新订阅。默认的随机候选没有经过用户网络实测；切换入口与切换出口应分开验证。

本地回环测试用于确认真实转发、配置隔离、零 KV 读取与协议正确性，不能代表公网加速幅度。实际效果还取决于本地运营商、Cloudflare 入口、出口服务和目标站点。自动化验证记录见 [validation.md](validation.md)。
