先理解：Pages、KV、部署，分别是什么？
  • Pages / Workers：程序运行的地方。后台页面、订阅接口和隧道代码都在这里执行。
  • KV：配置储物柜，保存节点设置、自定义地址、日志等。
  • 绑定：把这只储物柜接给程序，让它通过名称 KV 找到。
  • 部署：把构建好的程序发布出去。更新运行环境中的机密或绑定后，也要发布一次新部署。

本项目执行服务端代码，会使用 Workers 与 KV 的相关额度。可用计划、域名及可选服务各有政策，按自己账号页面确认当前费用和用量。查看官方额度说明 ↗

A PLACE OF YOUR OWN

准备自己的访问域名。

接下来用 edge.example.com 作为示例。实际操作时全部换成自己的域名，域名栏不填写 https:// 或 /admin。

根域名 · example.com
整个域名的 DNS 管理对象。把它接入 Cloudflare 后，可以在这里管理它的 DNS 记录。
子域名 · edge.example.com
给这套后台使用的单独入口。已有网站的读者，可以使用一个新的子域名。
↗

已有 Cloudflare 域名：确认域名在当前账号显示 Active 后，直接进入第 3 步。
暂不使用自定义域：可先用 Pages 分配的 *.pages.dev 地址验证后台；第 6 步仍需重新部署。

把整个域名的 DNS 接入 Cloudflare

操作路径Domains / 域名→Onboard a domain / 接入域名
  1. 输入根域名，继续。

    例如 example.com。部分界面将入口显示为「添加域名」或「添加站点」。选择适合自己的计划；页面有 Free 计划时，可查看限制后选用。

  2. 核对已有 DNS 记录。

    对照原 DNS 服务商，保留已有网站、邮箱、验证记录。自动扫描不一定包含全部记录，确认完整后再继续。

  3. 复制 Cloudflare 给你的两条名称服务器。

    NS（Nameservers）决定由谁回答域名的 DNS 查询。两条名称必须从自己的 Cloudflare 页面复制。

  4. 到域名注册商修改名称服务器。

    登录注册域名的网站，进入这个域名的「Nameservers / 名称服务器」设置，将原名称服务器替换为刚复制的两条并保存。这是在修改名称服务器设置。

  5. 回到 Cloudflare 检查状态。

    等待状态由 Pending 变为 Active / 活跃。DNS 传播需要时间，不要反复切换名称服务器。

Pages 支持使用外部 DNS 的子域名。无需为这个子域名强制更换整个域名的 NS，只需确认自己能新增 CNAME，第 6 步再按 Pages 提示配置。

若直接把根域名 example.com 绑定给 Pages，则需要把这个根域名接入创建 Pages 项目的同一 Cloudflare 账号。查看域名要求 ↗

还没有域名？了解 DNSHE 的注册步骤

已有域名可跳过。需要使用 DNSHE 时，从 官方注册页 ↗ 开始；可选后缀、注册条件、期限与续期方式，以当前页面为准。

  1. 填写可收信邮箱，设置并确认密码，按表单填写资料。阅读条款后注册，按后续页面与邮件提示完成验证。
  2. 登录客户区，打开「Free Domains / 免费域名管理」，进入注册操作，填写前缀并选择当前开放的后缀。
  3. 核对完整域名、费用、条件和到期时间，再提交。注册成功后，记录到期日与续期入口。
  4. 打开域名管理，确认可用的 DNS 功能。支持 NS 委派且被 Cloudflare 接受时，可按上面的 NS 步骤接入；仅支持记录管理时，可考虑第 6 步的外部 DNS 子域名 CNAME 路线。

NS 管理可能被服务商关闭，不能假定每个后缀都支持独立接入。以实际权限为准；注册成功后，仍需在 Pages 关联访问域名。DNSHE 管理说明 ↗

域名已经开启 DNSSEC，切换前要处理什么？

先按注册商流程停用旧 DNSSEC，再切换名称服务器。待 Cloudflare 激活后，按其指引配置新的 DNSSEC。这样可以避免旧签名记录与新 DNS 服务不匹配。查看官方接入流程 ↗

GIVE YOUR CONFIG A HOME

为配置，准备一个储物柜。

KV 命名空间保存后台的配置。先创建它，再把它绑定到即将部署的项目；现在不用手动往里面添加任何数据。

操作路径Storage & databases / 存储和数据库→Workers KV→Create instance / 创建实例
  1. 打开 Workers KV。

    在 Cloudflare 账号菜单中查找，或使用控制台搜索「Workers KV」。

  2. 创建命名空间。

    点击 Create instance。部分界面显示「创建命名空间」。名称填 brclio-edge-config，点击 Create / 创建。

  3. 确认列表中出现这个名称。

    记住它，第 5 步会从下拉菜单里选择。无需复制命名空间 ID 到后台表单，也无需添加测试键值。

其他协议、传输与代理工具怎么使用？

节点配置支持 VLESS / Trojan 的 WebSocket、gRPC gun / multi、XHTTP stream-one，以及 Shadowsocks AES-GCM 经 WebSocket 传输。客户端需支持所选组合；改动后保存并更新订阅。使用自定义域切换到 gRPC 时，检查该域名的 Network → gRPC 已开启，并使用 443、TLS 与 HTTP/2；未开启时可能返回 403。查看 gRPC 条件 ↗

ONE THING AT A TIME

遇到问题，先找到下一步。

用看到的现象查找，例如「KV」「522」「没有节点」。先检查当前这一步，再继续后面的操作。

全部问题

自行构建时，终端找不到 node、npm 或 package.json

使用 Release 部署包无需运行这些命令，可直接回第 1 步下载 ZIP。自行构建时，找不到 node / npm：确认已安装 Node.js，重新打开终端再检查版本。找不到 package.json：进入解压后的项目根目录，确认能看到这个文件，再执行 npm ci。

找不到部署 ZIP，或上传后出现 404 / 源码文本

回第 1 步下载 Release 附件 brclio-edge-pages.zip，其中包含完整的 _worker.js。不要用「Source code」或「Code → Download ZIP」得到的源码 ZIP 顶替。自行构建时，先处理第一条错误，等 npm run build 成功后再用 dist/brclio-edge-pages.zip。回到正确 Pages 项目，新建一次生产部署。

找不到 Pages 的拖放文件入口

确认进入 Pages 的 Direct Upload，而不是创建 Worker 的入口。Git 集成项目不能直接用控制台拖放更新；需使用其 Git / Wrangler 流程，或新建 Direct Upload 项目。

提示缺少管理员配置 / ADMIN

检查名称是否为全大写 ADMIN，是否保存到 Production。保存机密后创建新的生产部署，最新部署时间必须晚于配置变更时间。

提示没有 KV，或后台无法保存

检查是否添加了 KV namespace 类型的资源绑定，而不是文本环境变量；绑定名称必须精确为 KV，选中自己的命名空间。修正 Production 绑定后重新部署，仍失败时查看 Pages 运行日志的实际错误。

变量明明存在，程序仍然读不到

确认没有只设置 Preview。检查 Production 的变量、机密、绑定，再上传同一部署包创建新的生产部署。旧部署可能早于设置变更。

自定义域出现 522

先确认域名已经在 Pages 的 Custom domains 中关联，再核对 CNAME 指向自己的完整生产项目地址。只添加 CNAME 而没有关联 Pages 域名可能出现 522。等待自定义域显示 Active。

跨账号绑定出现 Error 1014 / CNAME Cross-User Banned

检查域名的 DNS 与 Pages 是否在不同账号。跨账号 CNAME 存在限制，记录保存成功不等于访问就绪；可优先采用 DNS 与 Pages 同账号的配置方式。截图中的「仅 DNS」不保证适用于所有跨账号情况。按 Cloudflare 官方 1014 说明 ↗ 检查。

域名一直 Pending，或 HTTPS 证书没准备好

核对注册商的 NS 是否为当前 Cloudflare 账号给出的值。检查旧 DNSSEC、同名 DNS 记录、CAA 对证书签发的限制，并按 Custom domains 中的实际提示处理。DNS 有传播时间，反复修改不会加速。

ADMIN 登录失败，或者忘记后台密码

输入后台的 ADMIN，不是 Cloudflare 密码。检查复制时有无多余空格。忘记时可在 Cloudflare 的生产机密中设置新的 ADMIN，再重新部署。固定 UUID 时，改管理员密码不会因此改变节点身份。

后台保存后，域名或 UUID 又变回原值

这些值可能由 HOST、UUID、PATH 等运行环境设置覆盖。需要改动相应 Cloudflare 环境配置并重新部署，单改后台表单不能覆盖服务端决定的值。

自定义地址没进入订阅，测速结果没有生效

检查优选来源为本地地址库，并关闭随机 IP。先保存地址列表，再保存主配置，最后到客户端更新订阅。点击「追加选中」只产生待保存的内容，两个保存步骤都要完成。

客户端更新后没有节点，或提示格式错误

重新复制完整订阅地址，保留 token。检查是否只保存了订阅分组而没有执行更新，以及客户端支持的输出格式。订阅 HTTPS 地址应放进订阅 URL 栏，单节点协议链接放进分享链接导入入口。查看客户端的实际解析日志。

订阅转换失败，Clash / sing-box 等格式无法获取

所选格式可能需要外部转换后端。先用自动识别或通用格式检查基础订阅，再按需核对转换服务的地址、可达性和响应。后台保存成功不代表外部转换服务可用。

后台正常，节点却连接失败

核对正式域名、UUID、端口、协议、传输和路径是否一致。保存后更新客户端订阅，先用默认 VLESS + WebSocket 做基础检查，再结合客户端和 Worker 的日志定位。后台可打开只说明管理页面链路正常。

测速服务全部失败，或显示停止

先少量使用 IPv4 检查当前浏览器能否访问探测服务；IPv6 还取决于本机网络支持。手动切换备用测速服务后再启动一轮。离开测速页或页面进入后台会主动停止；需要继续时回到页面重新点击。

测速数值很好，客户端仍连不上

浏览器测的是当前网络到探测服务的链路，不能替代实际隧道验收。先确认结果已保存到地址列表和主配置、客户端已更新订阅，再用客户端测试节点的真实连接。

概览显示用量不可用，是不是节点出问题了？

检查用量查询是否配置、凭据是否有效、查询服务是否可达。不可用不是零用量，也不能据此判断节点状态；节点连接和用量查询要分别验证。

没有找到对应条目。试试更短的关键词，例如「域名」「保存」或「连接」。

需要提交问题时，记录部署方式、客户端版本和具体错误。分享截图或日志前，隐藏 ADMIN、UUID、订阅 token 和代理凭据。
